# HaRu App 页面与功能架构

- 状态：已确认
- 确认日期：2026-07-24
- 目标平台：Android 手机优先，兼顾平板与横屏

## 1. 产品原则

1. App 是网站的官方原生客户端，不是网页外壳。
2. 手机端优先保证封面、标题和操作区域的可读性，默认使用单列视频流。
3. 搜索是全局内容入口，不占用底部一级导航位置。
4. 内容资产与账户设置分离：“媒体库”管理内容，“我的”管理身份与 App。
5. 收藏、观看历史和订阅均以已登录账号为边界；下载是设备级本机功能。
6. 直接 MP4 播放是主路径；WebView 仅可作为明确标注的兼容降级方案。
7. 页面必须完整覆盖加载、空数据、失败、离线、会话过期和重试状态。

## 2. 一级导航

底部导航固定为四项：

| 页面 | 核心问题 | 主要内容 |
| --- | --- | --- |
| 首页 | 现在看什么？ | 最新、热门、高评分、关注内容与快捷筛选 |
| 发现 | 如何按结构探索内容？ | 标签、分类、艺术家、频道、排行榜和随机探索 |
| 媒体库 | 我保存或消费过什么？ | 收藏、历史和订阅 |
| 我的 | 我是谁，App 如何设置？ | 用户资料、账户安全、设置、帮助、反馈和关于 |

一级页面应分别保留自己的导航栈、滚动位置和筛选状态。搜索页、观看页、集合页等二级页面不显示底部导航。

### 2.1 内容来源作为一级入口

R34V、Hanime 与 91porn 是三个地位相同的一级内容来源，各自占据一个底部导航入口，
可在设置中自由排序。三者的差异由来源自身的能力决定，界面按能力隐藏而非新建页面：

| 来源 | 一级入口内容 | 账号 |
| --- | --- | --- |
| R34V | 最新/热门/高评分/关注 + 取向与范围筛选 | 有 |
| Hanime | 频道浏览（最新上市、里番、泡面番等）+ 筛选 | 有 |
| 91porn | 站点分类（热门、精华、本周/上周排行、时长与排序分类） | 无 |

91porn 没有账号体系，因此不提供收藏、播放列表、订阅、评论和上传者，也不占用媒体库的
一级范围——它的下载与播放进度在设备级的「本机」范围查看。

## 3. 首页

### 3.1 页面结构

1. 顶部品牌区域与搜索入口。
2. 内容频道：最新、热门、高评分、关注。
3. 内容取向、时长和发布时间等快捷筛选。
4. 单列 16:9 视频卡片流。
5. 下拉刷新和自动分页。

手机紧凑宽度始终使用单列。窗口宽度达到平板级断点后，才允许根据可用空间切换为多列布局。

### 3.2 视频卡片

视频卡片至少显示：

- 缩略图和时长；
- 标题；
- 播放量、评分和发布时间（接口可用时）；
- 艺术家或上传者（接口可用时）；
- 收藏、入库、下载和分享入口。

视频卡片不提供长按预览，避免额外流量、误触和后台播放状态复杂化。

## 4. 搜索

搜索从首页顶部进入独立页面，同时允许发现页提供同一入口。

搜索页包含：

- 搜索历史与热门标签；
- 标签、分类和艺术家自动补全；
- 综合、视频、标签、艺术家和分类结果；
- 相关度、最新、热门、高评分、最长和随机排序；
- 内容取向、发布时间、时长、标签、分类、艺术家和已验证上传者筛选；
- 同类实体严格交集、跨类型交集、排除实体、最低点赞率和最低投票数；
- 可见且可逐项删除的筛选条件；
- 自动分页、空状态、失败状态和重试。

搜索历史不得跨账户混用；未登录状态下首版不持久化账户相关历史。

## 5. 发现

发现页用于结构化浏览，而不是复制首页视频流。

主要区域：

- 热门标签；
- 分类；
- 艺术家/模型；
- 频道；
- 视频与艺术家排行榜；
- 随机探索。

标签、分类、艺术家和频道统一进入“内容集合页”。集合页负责展示简介、统计、关注状态、排序、筛选和视频列表。

## 6. 媒体库

媒体库包含：

- 收藏；
- 观看历史；
- 关注/订阅。

未登录时，媒体库展示登录说明，但不伪造或创建匿名收藏和匿名历史记录。下载是独立的本机功能，在“我的”中管理，不要求登录。

## 7. 我的

### 7.1 已登录状态

- 头像、用户名、用户 ID 和账户状态；
- 编辑资料与网站个人主页；
- 上传内容及互动入口（接口支持时）；
- 下载管理；
- 账户与安全；
- App 设置；
- 帮助、反馈、关于、开源许可和版本更新；
- 退出登录。

### 7.2 未登录状态

- 明确的登录和注册入口；
- App 设置；
- 帮助与反馈；
- 关于、GitHub、开源许可和版本更新。

“我的”不得被简化为收藏列表或单个登录按钮。

## 8. 视频观看页

视频详情和播放器合并为统一观看页：

1. 顶部内嵌播放器；
2. 标题、播放量、评分、发布时间等元数据；
3. 喜欢、不喜欢、收藏、稍后观看、播放列表、下载和分享；
4. 艺术家、上传者与关注操作；
5. 简介、分类和可点击标签；
6. 相关视频。

播放器首版必须支持：

- 播放、暂停、拖动、全屏和横竖屏；
- 清晰度选择，并尽量保持切换前的播放位置；
- 默认清晰度与不同网络类型下的策略；
- 播放进度记忆；
- 播放源令牌过期后的自动刷新与恢复；
- 持久缓存和可配置后台播放；
- 明确的加载、缓冲、失败和重试状态。

## 9. 设置

设置至少包括：

- 外观：浅色、深色、跟随系统和主题偏好；
- 播放：默认清晰度、网络策略、自动播放、循环、进度记忆和屏幕行为；
- 内容：默认取向、隐藏标签、缩略图模糊和预览策略；
- 下载：默认清晰度、并发数、仅 Wi-Fi、存储空间和文件保留策略；
- 隐私：历史记录策略、清除缓存、清除账号本地数据；
- App：语言、更新通道、诊断信息、开源许可和版本信息。

## 10. 首版范围

首个公开版本必须形成完整闭环：

- 登录、会话恢复、会话过期处理和退出；
- 首页单列浏览；
- 搜索、排序和核心筛选；
- 发现页及统一集合页；
- 统一视频观看页；
- 收藏、本地分类库和观看历史；
- 后台下载与下载管理；
- 个人资料、上传者主页和精简设置入口；
- 更新检查、错误诊断和开源信息。

评分和订阅应进入首版。评论因使用率低且会显著增加详情页复杂度，不纳入 App 功能范围。
